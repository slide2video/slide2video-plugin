# Chapter video guide

How to build one chapter video with the slide2video engine. **LV** = the full `uv run "…/scripts/slide2video.py"` command line given to you by the make skill (or by whoever handed you this chapter). A chapter is a folder `WORK/chN/` with `script.json` and `scenes.js`; its images are in `assets/` next to them, or, when lessons live in a project folder, in the `assets:` folder `LV where "WORK/chN"` prints (scenes still refer to them as `assets/<file>`). Copy the idioms in `sample/` (next to this file). Also follow the style's guide: the `guide` path that `LV style <id>` prints (the id is in `WORK/style.txt`). It says who the videos talk to, their tone, scene order and length.

## Workflow
1. Write `script.json`. Top level: `chapter` (small top-right label, e.g. `"CHAPTER 2 · OSMOSIS"`), `title`, `out` (e.g. `"Chapter 2 - Osmosis and the Salty Potato Lab.mp4"`), optional `"music": "../music/bed.mp3"`, optional `"voice"` (ElevenLabs: `"jessica"`, the default, `"daniel"`, or any voice ID), optional `"narrator"`: `"auto"` (default: ElevenLabs if a key is set, else the free Microsoft voice, else the computer's own voice, else captions only), or one of `"elevenlabs"`, `"edge"` (free Microsoft voice; `"edge_voice"` picks it, default `en-US-AvaMultilingualNeural`), `"system"` (the computer's voice; `"system_voice"` picks it), `"none"` (captions only, timed at reading speed). With the computer's voice or captions only, word times are estimated, so reveals land within about half a second of the word. `scenes`: one object per scene with `id`, `say` (narration), optional `lead` (s before speech, default 0.5), `tail` (s after, default 0.7), `hold` (extra silent s, used for quiz countdowns), `min` (minimum s). Give each scene `slide` (the number of the deck slide it shows or talks about, from `## Slide N` in `WORK/deck/slides.md`): the one slide that matches it best, even when one slide is split over several scenes or is hidden in the deck. Leave it out only where no slide matches (your own quiz questions and answers, an outro that sums up). Players show that slide beside the video, so get it right.
2. `LV narrate "WORK/chN"`: one ElevenLabs take per scene, cached by text, so re-running only re-voices changed scenes. Prints each scene's start and duration.
3. Write `scenes.js`: when `plan.md`'s `Look:` line names a look, first `Engine.theme('<look>')` with it (`Look: none` means no `Engine.theme` line at all); then `Engine.assets({...})` and one `scene(id, draw, opts)` per scene id.
4. `LV stills "WORK/chN" t1 t2 ...` (absolute seconds; one per scene, late enough that its reveals have happened) → `build/stills.jpg`. Read it and fix problems; it also prints `cue miss` warnings for cue words that never occur in the narration.
5. `LV render "WORK/chN"` → the MP4 and a `.vtt` (it prints where).

## Engine API (globals)
`const { W, H, C, E, P, pop, theme, clamp, lerp, text, measure, card, circle, arrow, line, check, cross, img, clip, bg, heading, badge, tip, bullets, label, emoji, titleCard, intro, quizQ, quizA, recap, rr, molecule, wander, membrane, ring, table, rng, noise } = Engine;`
- `scene(id, (g, t, s) => {...}, opts)`: `g` = canvas 2D context (1920×1080), `t` = seconds since the scene started. `s.cue('word', n=0)` = local time the n-th occurrence of a word (prefix match, case- and punctuation-insensitive) is spoken; **sync every reveal to a cue word**. `s.after('word')` = when it ends. `s.end` = narration end, `s.dur` = scene length.
- `opts`: `dark: true` (dark background; adjusts label and captions), `bug: false` (hide the top-right label), `noCaptions: true`, `cut: true` (no crossfade), `sfx: [[cue, name, gainDb]]` where cue is seconds, `'word'` or `['word', n]`. A soft whoosh is added automatically at each scene change; keep sound effects tasteful (−12 to −16 dB).
- Sound effects available: `pop0` `pop1` `pop2` `pop3` (reveals), `sparkle0` `sparkle1` `sparkle2` (correct answers, big moments), `whoosh0` `whoosh1` `whoosh2`, `thump0` `thump1` (heavy landings), `zip0` `zip1` `zip2` (arrows, lines), `pluck0` `pluck1` `pluck2` `pluck3` (quiz questions, playful notes), `tape0` `tape1` `tape2`, `pencil0` `pencil1` `pencil2`, `crayon0` `crayon1`, `waves0`, `shutter0` (photos).
- Timing helpers: `P(t, start, dur=0.6, ease=E.out)` → 0..1; `pop(t, start)` = overshoot pop-in for scale; easings `E.lin/out/in/inOut/back/elastic`.
- `Engine.theme('<look>', {main, accent, tint})`: the lesson's look (the `Look:` line in `plan.md`), once at the top of `scenes.js`, the same in every chapter. The style's guide says which look fits the deck; with no `Look:` line, or `Look: none`, don't call it (there is no look called `none`). Looks: `classroom`, `math`, `history`, `literature`, `life`, `space`, `ocean`. It sets the backgrounds of `titleCard`, `quizQ`, `quizA` and `recap` and the colours below. Optional: `main` and `accent` (`'#hex'`) from the deck's own colours, `tint: ['#top', '#bottom']` for the dark backgrounds.
- `bg(g, kind, t)`: `'light'` (the look's light background: use it for content scenes) or `'dark'` (its dark one, for dark scenes with `dark: true`). Named backgrounds, when a scene needs a particular one: light `'paper'`, `'sand'`, `'lab'`, `'grid'`, `'parchment'`, `'lined'`; dark and animated `'night'`, `'blueprint'`, `'sepia'`, `'stage'`, `'canopy'`, `'cosmos'`, and `'ocean'` / `'deep'` (underwater: only for lessons about water or the sea). `'light'`, `'dark'` and the newer names need `Engine.theme` first; without it `bg` knows only `paper`, `sand`, `lab`, `ocean` and `deep`, as in earlier chapters.
- `heading(g, 'Title with *accent*', t, {kicker: 'Small caps line'})`: top-left title. Use on every content scene.
- `text(g, str, x, y, {size, weight, color, align, maxW, lh, alpha, accent, shadow, font})` → height. `y` = top of the text block. Markup `*accent color*`, `_bold_`. Wraps at `maxW`. `measure(g, str, opts)` → `{w, h, lines}`.
- `card(g, x, y, w, h, {fill, r, stroke, lw, alpha, shadow})`, `rr(g, x, y, w, h, r)` path, `circle(g, x, y, r, fill, {stroke, alpha})`, `line(...)`, `arrow(g, x1, y1, x2, y2, {color, w, head, prog, bend, dash, alpha})` (`prog` animates drawing, `bend` curves it).
- `check(g, x, y, size, prog)`, `cross(...)`, `badge(g, 'LABEL', x, yCenter, {fill, color, size, scale, alpha})`, `ring(g, x, y, r, k)`.
- `tip(g, 'text', t, atTime, {label: 'TEST TIP', size})`: callout card above the captions. 1–2 per scene for exam tips and traps (`label: 'TRAP!'` or `'WATCH OUT'`).
- `bullets(g, items[], x, y, t, times[], {size, maxW})`, `table(g, rows, x, y, colW[], {rowTimes, t, size, rowH})`, `label(g, 'text', px, py, tx, ty, k)` leader-line label.
- `img(g, key, x, y, w, h, {fit: 'cover'|'contain', r, zoom, panX, panY, alpha, shadow})`: images registered with `Engine.assets({key: 'assets/file.jpg'})`. Slow Ken Burns: `zoom: 1.05 + 0.02 * t`.
- `clip(g, 'assets/clip_name', frameCount, t, x, y, w, h, {fps: 24, loop: false, fit: 'cover', r})`: plays a JPEG frame sequence made by `LV frames` (an 8 s clip = 192 frames).
- `emoji(g, '💡', x, y, size, {scale, rot, alpha})`: great for icons. Emoji look slightly different on Windows and Mac.
- Science helpers: `molecule(g, x, y, 'water'|'salt'|'sugar'|'o2'|'co2'|color, scale, alpha)`, `wander(i, t, {x, y, w, h}, seed)` → `[x, y]` for particle fields, `membrane(g, x, y1, y2, t)`.
- Standard scenes: `titleCard(g, t, s, {kicker, title, sub, emojis, bg})` (a section title inside a chapter, never the opening), `quizQ(g, t, s, {n, q, choices, emoji, badge})` (countdown ring during `hold`; `badge` replaces the `QUIZ · QUESTION n` label; `numbered: true` numbers the lines 1., 2., 3. instead of A., B., C.; a long line shrinks to fit its card), `quizA(g, t, s, {answer, why})`, `recap(g, t, s, items, times, {title, kicker, gap, next, nextAt})`.
- Opening scene: `intro(g, t, s, {mood, title, kicker, sub, by, logo, name, photo, main, accent, panel, emojis, at})` draws the first scene as a short motion piece: a moving backdrop, the logo, and the title revealed word by word. It must not look like the deck's first slide, which players show beside the video: never rebuild the title slide (a centred stack of logo, title and subtitle) as the opening, and never open with `titleCard`. `mood` (required) is the motion; the style's guide says which suit it.
  - Dark moods: `'polished'` (a field of tiles moving in a slow wave, a light sweep, the title sliding up out of a mask), `'cinematic'` (a letterbox opening on `photo`, a full-bleed photo with a slow push-in, the title coming into focus; a dark sky without one), `'energetic'` (dark, slashing stripes, speed lines, the title slamming in), `'themed'` (the lesson's own title background from `Engine.theme`, white text, the title sliding up: calm and serious), `'kinetic'` (giant outlined words of the title marching across in tilted rows, an accent sweep, the title wiped in, big: bold and confident), `'split'` (a slanted dark panel slides in over `photo`, or over a band of the deck's colours, an accent seam drawn down the cut), `'flare'` (warm light leaks and a lens flare drifting over a dark frame, the title coming into focus: premium, warm), `'constellation'` (a night sky where stars join into a slowly turning constellation: ideas, science, data), `'glitch'` (fine scanlines, dashed rings with a red and cyan split, a brief glitch only as things arrive: technology), `'spotlight'` (a spotlight sweeps across a dark stage and settles on the title: a launch, an award, a reveal), `'duotone'` (opens dark on one word of the title with `photo` seen through it, zooms through the word into the photo in the deck's two colours; a soft abstract in them without a photo), `'typewriter'` (a dark screen, lines of code typing themselves, the title typed with a cursor: software, tools, how-to), `'burst'` (rays turning around a glowing core, rings and sparks as the title lands: celebrations, results, openings), `'parallax'` (translucent panes at different depths flying in and drifting, one holding `photo`: products, services), `'countdown'` (3, 2, 1, then a stopwatch, stadium beams and a strip of lights: sport, training, events).
  - Light moods: `'calm'` (light background, soft rings and a pulse line, gentle fades), `'playful'` (paper, floating shapes, the title bouncing in, optional `emojis`), `'liquid'` (soft blobs of the deck's colours drifting like a gradient mesh: modern, friendly), `'isometric'` (cubes drop into an isometric sculpture, the title dropping in with depth: building, planning, structure), `'ribbon'` (folded paper ribbons fold out up the side, the words flipping in: warm, crafted), `'route'` (a map with contour lines, a dotted route drawing itself between pins: journeys, trips, places, a path in steps), `'flow'` (quiet translucent waves flowing in, light rising: health, wellbeing, gentle topics). With `Engine.theme`, `playful` also takes the look's light background and colours.
  - **One mood from several, so videos differ.** `mood` may be a list, e.g. `mood: ['split', 'kinetic', 'parallax', 'flare']`: `intro` picks one by the title, so two decks given the same list rarely open the same way, while the same title always gives the same pick, in every render. When the style's guide lists several moods, pass them all as the list, leaving out only those that clearly don't fit this deck (`route` when the deck isn't about places or a path, `countdown` when it isn't about sport or an event, `typewriter` when it isn't about software or tools). Never narrow the list to one by taste: the same style would then open every video the same way. From a list, `cinematic` is picked only when `photo` is given and `split` only when it isn't, so keep both in a list either way. With a list, `photo` is drawn only when the picked mood draws photos, and `emojis` only when it is `playful`.
  - `title` (required), `kicker`, `sub` and `by` are the title slide's own lines, as written: long lines shrink, wrap (also Chinese, Japanese, Thai) and at worst end in "…", always between the logo and the captions. `logo` is an `Engine.assets` key; leave it out when there is no logo, and give `name` instead (a missing logo draws `name`, with a warning). Give both only when the logo doesn't already spell the name: the name is drawn beside it. `panel: true` puts the logo on a panel (the dark moods do by default; a logo too light for its background always gets one). `main` and `accent` are `'#hex'` colours (the deck's when the style uses them): every text colour is checked against its background and darkened or lightened until it reads, so any brand colour is safe. `photo` (an `Engine.assets` key) is drawn by `cinematic`, `split`, `duotone` and `parallax` only, `emojis` by `playful` only. `at: {logo, kicker, title, sub, by}` are local times, e.g. `s.cue('word')`, so each line lands as it is said; left out, they follow one another in the first 3 to 4 s. A wrong option stops the render with a message saying what to fix. It changes only the drawing: the scene's narration, timing and length stay as `script.json` makes them. These go on the scene's own options, never inside `intro`'s (an unknown option stops the render): `scene('hook', (g, t, s) => intro(g, t, s, {...}), { bug: false, dark: true })`, with `dark: true` for a dark mood and left out for a light one (with a list of both kinds, `dark: true`).
- Layout: margins x 120..1800; headings y 40..170; content y 210..900; **captions are drawn automatically below y ≈ 930**, so keep content above 900. Minimum text size 30 px (prefer 36 or more). One idea per scene; big, bold, colorful; animate things in as they are spoken.
- Colours: the look's roles first: `C.head` (headings, dark text), `C.main` (kickers, bullets, lines), `C.accent` (`*accent*` words, badges, tips), `C.glow` (accent on dark backgrounds), `C.soft` (light text on dark), `C.note`. Fixed colours: `C.ink, C.sun, C.leaf, C.coral, C.purple, C.pink, C.grey, C.water, C.navy, C.sea, C.teal, C.aqua, C.foam`. Prefer the roles so the scene follows the look.

## Assets
Copy each deck image you use with `LV asset "WORK/deck/media/<file>" "WORK/chN/assets/<name>.jpg"` (straightened, at most 1600 px, transparent PNGs flattened; use a `.png` target to keep transparency). Use the contact sheets to pick them. A missing asset, clip frame or scene stops `stills` and `render` with an error naming it.

## Numbers from the deck
The deck's numbers are its facts. The video shows them clearly and beautifully; it never changes them.
- Every number, unit and label shown or said is exactly as in `WORK/deck/slides.md` (or the other files the teacher gave): no rounding or re-rounding, no recomputing, averaging, converting or estimating. "Down 0.8 points" stays 0.8.
- A chart in the deck (`[Chart: …]` in `slides.md`, with one line of values per series) is drawn as the same kind of chart (column, bar, line, pie…) with every category and every series, in the deck's order and with the deck's values. Never drop a category or a series, never add one, never merge charts or build a new chart out of other slides' numbers, and never leave a deck chart out.
- A table keeps every row and column it has in the deck. Revealing rows one at a time is fine; the finished scene shows them all.
- A number the deck doesn't state (a total, a difference, a growth rate, an average) is never shown or said, even when it's easy to work out.
- Allowed: saying a number in words for the voice ("forty eight point two million dollars"); highlighting it, animating it or choosing the order of the reveal; showing a pie's shares that add up to 1 as the same percentages (0.58 → 58%).
- If a chart reads `[Chart not read: …]` or a value is unclear, don't guess: it goes in the brief's "Possible issues in the slides" and is asked about.
- Before `stills`, check every chapter: find each number in its `script.json` and `scenes.js` in `slides.md`, and for each deck chart and table the chapter covers, check that every one of its values is on screen. Fix any difference before going on.

## Narration style
- Text-to-speech friendly: spell symbols as spoken ("C O two" or "carbon dioxide", "ten point three percent", "three hundred milliliters"); no abbreviations like "e.g."; no emoji in `say`. Captions show the `say` text, so keep it clean.
- Never invent facts or statistics beyond `brief.md`, and say the deck's numbers exactly (see "Numbers from the deck").
